# 새로운 Copilot Studio 환경을 사용하여 에이전트 만들기

## 시나리오

이 연습에서는 다음 작업을 수행합니다.

- 새로운 Copilot Studio 환경으로 전환
- 자연어 지침을 사용하여 에이전트 만들기
- 에이전트가 자율적으로 사용할 수 있는 미리 빌드된 작업 추가
- 에이전트를 테스트하고 추론 동작 관찰
- 테스트 결과에 따라 지침 구체화

이 연습을 완료하는 데 약 **30**분이 소요됩니다.

### 학습 내용

- 새로운 Copilot Studio 환경과 클래식 인터페이스의 차이점
- 토픽 트리 대신 지침을 사용하여 에이전트를 구성하는 방법
- 에이전트가 지식과 작업을 선택하기 위해 자율적으로 추론하는 방법
- 에이전트 동작을 개선하기 위해 지침을 반복적으로 수정하는 방법

### 실습 주요 단계

- 새로운 Copilot Studio 환경으로 전환
- 설명을 사용하여 에이전트 만들기
- 에이전트 지침 작성 및 구체화
- 미리 빌드된 작업 추가
- 테스트 및 반복 개선

### 필수 조건

- Microsoft Entra ID 계정이 있어야 합니다.
- Copilot Studio 라이선스가 있거나 [무료 평가판](https://go.microsoft.com/fwlink/p/?linkid=2252605)에 등록되어 있어야 합니다.
- 에이전트 및 관련 자산을 만들 수 있는 Power Platform 환경과 솔루션에 액세스할 수 있어야 합니다.
- 다음 중 하나를 사용할 수 있습니다.
   - **ILT 설정** 실습에서 만든 환경 및 솔루션
  - 사용자가 보유한 기존 환경 및 솔루션
- 환경과 솔루션이 아직 준비되지 않은 경우 계속하기 전에 **ILT 설정** 실습의 단계를 완료하세요.

> [!IMPORTANT]
> 본 과정은 클래식 Copilot Studio 환경을 사용합니다 Copilot Studio 화면이 이 미션의 스크린샷과 다르게 보인다면, 오른쪽 위의 **새 환경(New Experience)** 를 꺼서 여기서 사용하는 **클래식 환경(classic experience)** 로 전환하세요.

## 핵심 개념: 지침 기반 에이전트

새로운 Copilot Studio 환경은 토픽 작성 캔버스를 더 간단한 지침 기반 모델로 대체합니다.

| 클래식 환경 | 새로운 환경 |
|---|---|
| 토픽 트리와 트리거 문구로 에이전트 동작 정의 | 자연어 지침으로 에이전트 동작 정의 |
| 작성자가 명시적인 대화 흐름을 노드별로 구성 | 에이전트가 응답 방법을 동적으로 추론 |
| 토픽, 조건 및 분기로 대화 라우팅 제어 | 지침, 지식 및 작업으로 에이전트가 수행할 작업 결정 |
| 작업을 사용하려면 Power Automate 워크플로를 빌드하고, 입력/출력을 구성하고, 도구로 추가해야 함 | 미리 빌드된 커넥터 작업을 Copilot Studio에서 직접 추가하므로 워크플로를 작성할 필요가 없음 |

새로운 환경은 개방형이며 상황에 따라 달라지는 대화를 처리해야 하는 에이전트에 가장 적합합니다. 보장되고 감사 가능한 단계의 순서가 필요한 경우(예: 특정 순서로 구조화된 데이터 수집)에는 이후 실습에서 다루는 클래식 환경이 여전히 적합합니다.

## 실습 1 - 새로운 Copilot Studio 환경으로 전환

### 작업 1.1 – 새로운 환경 열기

1. `https://copilotstudio.microsoft.com/`의 **Copilot Studio** 홈페이지로 이동하고 메시지가 표시되면 로그인합니다.

1. 페이지 위쪽에서 이 연습에 사용하려는 환경에서 작업 중인지 확인합니다.

1. **새 환경 사용**을 안내하는 배너 또는 알림이 표시되면 선택합니다.

   또는 **새 환경** 토글이 표시되지 않는 경우 `https://copilotstudio.preview.microsoft.com/`로 직접 이동하여 새로운 환경을 엽니다.

   > [!NOTE]
   > 새로운 환경이 해당 환경의 기본값일 수 있습니다. 인터페이스가 이미 이 실습의 단계와 일치한다면 새로운 환경을 사용 중이므로 연습 2로 진행할 수 있습니다.

### 작업 1.2 – 새로운 인터페이스 검토

에이전트를 만들기 전에 잠시 새로운 환경의 구성 방식을 살펴봅니다.

1. 왼쪽 탐색 영역에서 **홈**, **에이전트 운영**, **채팅**, **에이전트**, **워크플로**의 주요 섹션을 확인합니다.

1. **에이전트** 페이지에는 기존 에이전트가 표시됩니다. 새로운 환경에서 만든 에이전트에는 토픽 캔버스가 없습니다. 에이전트의 동작은 에이전트 **개요** 페이지의 지침, 지식 및 작업만으로 정의됩니다.

1. 탐색 영역에 **토픽** 섹션이 없는 것을 확인합니다. 새로운 환경에서는 토픽이 작업과 지침으로 대체됩니다.

## 실습 2 - 에이전트 만들기

이 실습에서는 Contoso라는 가상 회사의 IT 지원 에이전트를 만듭니다. 에이전트는 직원이 일반적인 IT 문제를 해결하고 지원 티켓을 제출하도록 도와줍니다.

### 작업 2.1 – 에이전트 만들기

1. 왼쪽 탐색 영역에서 **홈**을 선택합니다.

1. **홈 > 채팅** 페이지의 빌드 프롬프트 텍스트 상자에 다음 설명을 입력합니다.

   ```prompt
   당신은 Contoso의 IT 지원 에이전트입니다. 직원들이 암호 재설정, 소프트웨어 설치 문제, 네트워크 연결과 같은 일반적인 IT 문제를 해결할 수 있도록 지원합니다. 문제를 해결할 수 없는 경우 직원이 지원 티켓을 제출할 수 있도록 도와줍니다.
   ```

   > [!NOTE]
   > 새로운 환경은 입력한 설명을 사용하여 초기 지침 집합을 자동으로 생성합니다. 계속하기 전에 해당 지침을 검토하세요.

1. 추가 확인 질문이 표시되면 질문에 답하여 에이전트가 더 정확한 지침을 생성하도록 합니다. 예를 들면 다음과 같습니다.

   - 직원이 IT 지원 티켓을 제출하는 방법을 묻는 경우 ServiceNow, Jira, Dynamics 365 또는 Zendesk 대신 IT 기술 지원팀에 지원 요청 이메일을 보내는 옵션을 선택합니다.
   - 에이전트가 기술 자료, SharePoint 사이트 또는 웹 사이트를 참조해야 하는지 묻는 경우 외부 지식 소스가 필요하지 않음을 나타내는 옵션을 선택합니다.

   질문을 진행하려면 **계속**을 선택하고, 해당하지 않는 질문은 **건너뛰기**를 선택합니다. 완료되면 **제출**을 선택합니다.
   ![alt text](image-13.png)
   ![alt text](image-14.png)

   > [!NOTE]
   > 설명과 환경에 따라 추가 확인 질문이 다르거나 전혀 표시되지 않을 수 있습니다. 이러한 질문이나 답변 옵션이 정확히 표시될 것으로 예상하지 말고 실습 시나리오에 맞게 답변하세요.

1. 지원 요청을 보낼 때 에이전트가 사용할 이메일 주소를 입력하라는 메시지가 표시되면 관리자 이메일 주소를 입력한 다음 **제출**을 선택합니다.
   ![alt text](image-15.png)

1. 자동 생성된 에이전트를 검토한 후, 에이전트를 선택하여 **빌드** 탭을 엽니다.
   ![alt text](image-16.png)

   ![alt text](image-18.png)

### 작업 2.2 – 자동 생성된 지침 검토 및 구체화

1. 에이전트의 **빌드** 탭에서 **지침** 섹션을 찾습니다.

1. 설명을 기반으로 생성된 지침을 검토합니다. 지침에는 에이전트의 목적, 어조 및 일반적인 동작이 설명되어 있어야 합니다.

1. **지침** 섹션에서 다음 지침을 추가하여 지침을 업데이트한 다음 **저장**을 선택합니다.

   ```prompt
   ## 지침
   - 항상 전문적이고 친절한 어조로 응답합니다.
   - 암호 재설정 요청의 경우 티켓 생성을 제안하기 전에 직원에게 https://aka.ms/sspr의 셀프 서비스 포털을 안내합니다.
   - 해결할 수 없는 문제의 경우 티켓을 제출하기 전에 직원의 이름, 이메일 주소 및 문제에 대한 간단한 설명을 수집합니다.
   - 하드웨어 오류를 추측하지 않습니다. 물리적 하드웨어 문제의 경우 항상 IT 지원 데스크에 직접 문의하도록 안내합니다.
   - 직원의 문제를 해결할 수 없는 경우 이메일 보내기 작업을 사용하여 직원의 이름, 이메일 및 문제 설명과 함께 helpdesk@contoso.com의 IT 기술 지원팀에 알립니다.
   ```
   
   > [!NOTE]
   > 새로운 환경에서 지침은 에이전트 동작을 제어하는 기본 방법입니다. 잘 작성된 지침은 추가 구성의 필요성을 줄이고 에이전트의 동작을 더 예측 가능하게 만듭니다.

   ![alt text](image-19.png)

## 실습 3 - 테스트 및 구체화

이 실습에서는 에이전트를 테스트하고 응답하기 전에 에이전트가 추론하는 방식을 관찰합니다.

### 작업 3.1 – 미리 보기 탭 열기

1. 페이지 위쪽에서 **미리 보기** 탭을 선택하여 에이전트를 테스트합니다.

1. 에이전트를 테스트하면 각 응답 위에 추론 요약이 자동으로 표시되어 에이전트가 수행할 작업을 결정한 방식을 설명합니다. 해당 요약에서 **자세히 보기**를 선택하여 전체 추론 추적을 펼칩니다.

   > [!NOTE]
   > 추론 추적은 새로운 환경의 주요 기능입니다. 에이전트가 고려한 지식 소스 또는 작업과 그 이유를 보여 줍니다. 예를 들어 **로드된 기술** 항목은 에이전트가 호출한 작업 또는 기술을 나타냅니다.

### 작업 3.2 – 지침 테스트

1. **미리 보기** 탭 위쪽에서 **새 채팅**을 선택합니다.

1. 다음 프롬프트를 입력합니다.

   ```prompt
   암호를 잊어버려서 로그인할 수 없습니다.
   ```

   작성한 지침에 따라 에이전트는 티켓 생성을 제안하기 전에 셀프 서비스 포털을 안내해야 합니다.
   ![alt text](image-20.png)

### 작업 3.3 – 에이전트의 추론 동작 테스트

1. **미리 보기** 탭 위쪽에서 **새 채팅**을 선택합니다.

1. 다음 프롬프트를 입력합니다.

   ```prompt
   노트북 전원이 전혀 켜지지 않습니다.
   ```

   작성한 지침에 따라 에이전트는 하드웨어 오류를 원격으로 해결하지 않고 IT 지원 데스크에 직접 문의하도록 안내해야 합니다. 에이전트가 사용자를 대신하여 지원 티켓 제출을 제안할 수도 있습니다.

   ![alt text](image-21.png)

1. 메시지가 표시되면 이름, 이메일 및 문제에 대한 간단한 설명을 제공합니다.

### 작업 3.4 – 테스트 결과에 따라 지침 구체화

1. 세 번의 테스트 세션에서 에이전트가 응답한 방식을 검토합니다.

1. 응답이 의도한 동작과 일치하지 않는 경우 **빌드** 탭을 선택하고 **지침** 섹션에서 관련 지침을 조정합니다.

   예를 들어 에이전트가 암호 재설정 시 셀프 서비스 포털을 언급하지 않았다면 다음과 같이 지침을 더 명확하게 만듭니다.

   ```prompt
   - 모든 암호 관련 요청의 경우 다른 지원을 제공하기 전에 항상 첫 번째 단계로 https://aka.ms/sspr을 안내합니다.
   ```

1. **게시**를 선택한 다음 **저장 및 게시**를 선택하고 해당 시나리오를 다시 테스트합니다.

   > [!NOTE]
   > 지침을 반복적으로 수정하는 것은 새로운 환경의 기본 조정 메커니즘입니다. 표현을 조금만 변경해도 에이전트 동작이 크게 달라질 수 있습니다.

   ![alt text](image-23.png)

## 요약

이 실습에서는 새로운 Copilot Studio 환경을 사용하여 지침 기반 IT 지원 에이전트를 만들었습니다. 자연어 지침만으로 동작을 구성하고 Power Automate 워크플로를 빌드하거나 페이지를 벗어나지 않고도 미리 빌드된 커넥터 작업을 Copilot Studio에 직접 추가했습니다. 도구를 추가하기 위해 워크플로를 작성하고, 입력 및 출력을 구성하고, 별도로 게시해야 했던 실습 03과 비교할 때 새로운 환경은 단순한 작업의 작성 노력을 크게 줄여 줍니다. 또한 **미리 보기** 창의 추론 추적을 사용하여 에이전트가 응답을 생성하기 전에 수행할 작업을 결정한 방식을 관찰했습니다. 이제 클래식 환경과 새로운 환경을 모두 사용해 보았으므로 각 시나리오에 적합한 방식을 선택할 수 있습니다. 개방형 대화에는 지침 기반 방식을 사용하고, 보장되고 감사 가능한 단계의 순서가 필요한 경우에는 클래식 토픽과 워크플로를 사용합니다.
